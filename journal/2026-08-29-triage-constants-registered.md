# 2026-08-29 · 정정 — "새 수치 상수를 하나도 만들지 않는다" 는 거짓이었다

`journal/2026-08-29-triage-score.md` §"설계·구현 중 세 번 틀렸고" 의 마지막 문단이 이렇게
적었다:

> 확정안은 **새 수치 상수를 하나도 만들지 않는다.**

**틀렸다.** 같은 항목을 쓴 직후 구현물을 다시 훑다가 잡았다. `src/msa/triage.py` 는 수치
상수를 **여섯 개** 만든다:

| 상수 | 값 | 하는 일 |
|---|---:|---|
| `EVIDENCE_CAP` | 0.50 | 판정을 만든 축의 증거가 미검증일 때 J 상한 |
| `EVIDENCE_CAP_REFUTED` | 0.25 | 대장에서 `refuted` 가 나왔을 때 J 상한 |
| `UNJUDGED_PENALTY` | 0.50 | C 감점 — 생존 판정 불가 |
| `RED_FLAG_PENALTY` | 0.15 | C 감점 — 레드플래그 1건당 |
| `RED_FLAG_MAX` | 2 | C 감점 상한 건수 |
| `PARTIAL_PENALTY` | 0.10 | C 감점 — 입력 결측 |

원래 하려던 말은 **"시장 데이터 위에 새 임계를 긋지 않았다"** 였다 — 낙폭 기준선은 기존
선언값 `PULLBACK_MARK` 를 재사용하고 낙폭 순서는 백분위라 눈금이 없다는 뜻이다. 그건
지금도 사실이다. 그러나 쓴 문장은 그 뜻이 아니었고, **그대로 읽으면 거짓**이다.

## 왜 이게 사소하지 않은가

`docs/24`(근거 레지스트리)가 존재하는 이유가 정확히 이 드리프트다. §0 이 기록한 상태는
"수치 상수 58개, 코드에 근거 주석이 붙은 것 0개" 였다. 근거 없는 상수 자체는 규칙 위반이
아니다 (`CLAUDE.md` §1 후자 절 — 없으면 없다고 적는다). **위반은 없는 것을 없다고 안 하고
"만들지 않았다" 고 말하는 것**이다.

## 무엇을 했나

여섯 전부와 `PULLBACK_MARK` 를 `msa.basis` 레지스트리에 `NoBasis`(선언값)로 등록하고
`FILTER_CONSTANTS` 에 올렸다. 이제 **값을 바꾸면 근거도 같이 고치라고 CI 가 막는다**
(`tests/test_basis.py::test_registry_value_matches_the_live_constant`).

- **`hard`·`gate` 태그는 붙이지 않았다.** 이 값들은 아무것도 자르지 않는다 — 읽는 순서만
  정한다. 붙이면 `weakest_links()` 가 "근거 없이 자르는 값" 으로 잘못 센다.
- **`PULLBACK_MARK` 은 원래 레지스트리에 없었다.** 자기 주석이 *"사람이 실제로 행동하는
  유일한 출력이 여기 걸려 있으므로 검토 대상에서 빼지 마라"* 라고 적어 뒀는데도 그랬다.
  2026-08-29 에 쓰임이 하나 늘어(결론 문장 → 트리아지 구획 경계) 등록할 자리가 됐다.
  **값은 그대로 두고 쓰임만 늘렸다.**
- `TRIAGE_WEIGHTS`·`R_WEIGHTS` 는 넣지 않았다 — `AXIS_WEIGHTS`·`S_WEIGHTS` 가 안 들어 있는
  것과 같은 이유다. 레지스트리는 스칼라 임계를 추적하고, 배분 벡터의 근거는 설계 문서
  §4.2 가 문장으로 진다.

`triage.py` 독스트링과 설계·계획 문서의 같은 문장도 고쳤다. **이 저널 항목은 고칠 수
없으므로**(`CLAUDE.md` §6) 앞 항목을 수정하는 대신 이 항목을 새로 쓴다.
