# 25. 설계 질문 9 — L2 는 제거됐다. 매크로가 다시 들어온다면 어떤 모양이어야 하나

작성 2026-08-29. **사전 등록 문서다.** 이 문서가 승인된 형태로만 구현한다 (`CLAUDE.md` §1).

## 1. 왜 이 질문이 다시 열리는가

`journal/2026-08-23-l2-removed.md` 가 L2(거시 인과 DAG)를 제거했고, `CLAUDE.md` 머리말이
못박았다:

> 되살리려면 **revert 가 아니라 새 설계 질문과 사전 등록**이 필요하다.

2026-08-29 에 사용자가 시스템을 헷지펀드 조직 구조로 키우라고 지시했고, 그 조직도에서
**매크로 스트래티지스트 자리가 비어 있다** (설계 §2). 그래서 질문이 다시 열린다.

**그러나 이 문서는 L2 를 되살리자고 제안하지 않는다.** 제거된 것과 제안하는 것이 다른
물건임을 §3 이 보인다.

## 2. 무엇이 제거됐었나 — 그리고 왜

L2 는 **거시 인과 DAG** 였다: 금리·달러·유가 같은 거시 변수에서 테마까지의 인과 그래프를
세우고, 그 그래프로 테마 점수를 조정하려 했다. 제거 사유(`docs/13` §9 → C안)의 핵심은
둘이었다:

1. **인과 그래프를 검정할 방법이 없다.** 노드와 간선을 사람이 선언하는데, 그 선언이 맞는지
   묻는 검정이 설계되지 않았다. 검정 없는 층이 점수를 **조정**하면 그 조정은 근거 없는
   자유도다.
2. **자유도가 폭발한다.** 거시 변수 × 테마 × 시차의 조합이 크고, 그중 무엇을 쓸지 고르는
   행위 자체가 `CLAUDE.md` §1 이 금지한 탐색이다.

두 사유 다 **"점수를 조정한다"** 는 전제에 붙어 있다. 그 전제를 빼면 사유도 같이 빠진다.

## 3. 제안 — 점수를 조정하지 않는다. 읽는 순서만 민다

| | 제거된 L2 | 이 문서의 P2 |
|---|---|---|
| 산출 | 거시 → 테마 인과 그래프 | `cycle_class` 8종에 대한 **3값 판정** |
| 쓰임 | 테마 **점수**를 조정 | 트리아지 **R 축의 계수** |
| 주장 | "이 테마가 더 오를 것이다" | "이 차트를 나중에 열어라" |
| 자유도 | 변수×테마×시차 | **8칸 × 3값** — 그 이상 없다 |
| 검정 | 설계되지 않음 | **필요 없다 — 수익률을 주장하지 않으므로** |
| 케이던스 | — | 주 1회 |

### 3.1 왜 `cycle_class` 인가 — 새 분류를 만들지 않는다

`state/themes.yaml` 이 이미 테마마다 `cycle_class` 를 선언하고 있다. 8종이고 분포는 이렇다
(2026-08-29 실측, 134 테마):

| `cycle_class` | 테마 수 | 묻는 것 |
|---|---:|---|
| `credit_rate` | 24 | 금리·신용 사이클에 걸린다 |
| `discretionary_demand` | 21 | 가계 재량 지출에 걸린다 |
| `commodity_supply` | 20 | 원자재 공급 사이클에 걸린다 |
| `secular_growth` | 17 | 구조적 성장 — 거시에 덜 걸린다 |
| `inventory` | 15 | 재고 사이클에 걸린다 |
| `capex_program` | 15 | 설비투자 프로그램에 걸린다 |
| `policy_program` | 13 | 정책·예산 집행에 걸린다 |
| `secular_risk` | 9 | 구조적 쇠퇴 위험 |

**이 분류는 M2 에서 이미 선언됐고 이 문서가 만들지 않는다.** 매크로 분석가는 새 축을 만드는
것이 아니라 **이미 있는 8칸에 오늘의 판정을 붙일 뿐**이다. 자유도가 8×3 으로 고정되는 것이
L2 와의 결정적 차이다.

### 3.2 산출 계약

`state/regime/<week>.yaml`:

```yaml
asof: 2026-08-29
week: 2026-W35
classes:
  credit_rate:
    verdict: headwind          # tailwind | neutral | headwind
    mechanism: "…"             # 왜 그렇게 보는가 — 한 문단
    invalidations:             # **비면 저장 거부** (CLAUDE.md §5)
      - "10년물이 3.5% 아래로 내려가면 이 판정은 무효다"
    evidence:                  # **비면 저장 거부** (CLAUDE.md §3)
      - claim: "…"
        source_url: "https://…"
        date: 2026-08-27
        reliability: high
```

기존 L3 계약을 **그대로 승계한다** — 무효화 조건 없는 판정은 저장되지 않고(§5), 출처 없는
주장도 저장되지 않는다(§3). 새 스키마 규약을 발명하지 않는다.

### 3.3 점수에 들어가는 방식 — 여기가 이 문서의 핵심이다

```
R ← R · REGIME_TILT[verdict]      # tailwind 1.00 · neutral 0.85 · headwind 0.70
```

**R 축에만 곱한다. J 와 C 는 못 건드린다.**

- **J(판정 신뢰도)를 못 건드리는 이유**: 매크로 레짐은 그 테마의 가치함정 판별이 옳은지에
  대해 아무 말도 하지 않는다. 금리가 오른다고 `managed_care` 의 증거가 더 검증되지 않는다.
- **C(재무 명료도)를 못 건드리는 이유**: 매크로는 그 회사의 재무제표를 읽지 않았다.
- **R(열람 시급성)만 건드리는 이유**: R 이 답하는 질문이 *"지금 이 차트가 할 말이 있는가"*
  이고, 역풍 레짐은 정확히 그 질문에 "지금은 덜 하다" 고 답한다.

**구획은 못 건드린다.** 역풍이어도 I-A 에서 I-B 로 내려가지 않는다 — 구획은 판별과 낙폭이
정하는 것이고 매크로는 둘 다에 대해 발언권이 없다. 이 성질을 테스트가 강제한다.

### 3.4 계수 1.00 / 0.85 / 0.70 — 선언값이고 근거가 없다

**없다고 적는다** (`CLAUDE.md` §1 후자 절). 세 값을 고른 근거는 "순풍은 그대로 두고, 중립은
조금, 역풍은 그보다 더 민다" 는 서술뿐이고, 0.85·0.70 이어야 할 문헌은 없다.

- `msa.basis` 레지스트리에 `NoBasis` 로 등록한다. 값을 바꾸면 CI 가 근거도 고치라고 막는다.
- **`hard`·`gate` 태그를 붙이지 않는다** — 아무것도 자르지 않는다.
- 결과를 보고 옮기지 않는다. 옮기려면 새 설계 질문이다.

## 4. 이 설계가 답하지 못하는 것 — 미리 적는다

1. **레짐 판정이 맞았는지 잴 수 없다.** 트리아지 자체가 검정 불가이므로(설계 §8.3) 그 계수도
   검정 불가다. 이것은 결함이 아니라 **선택한 성질**이다 — 검정 가능한 물건을 만들려면
   수익률을 주장해야 하고, 그 순간 `docs/15` 관문과 사전 등록이 필요해진다.
2. **8칸은 거칠다.** 같은 `credit_rate` 안에서도 은행과 리츠는 금리에 반대로 반응할 수 있다.
   더 잘게 쪼개면 자유도가 늘어나고 그것이 L2 가 죽은 이유다. **거친 채로 둔다.**
3. **주간이라 늦다.** 레짐이 하루 만에 바뀌면 못 따라간다. 매일 돌리면 크레딧이 들고 같은 날
   두 번 돌렸을 때 다른 값이 나와 재현성을 잃는다 (사용자가 2026-08-29 에 **비대칭 케이던스**를
   고른 이유가 이것이다).

## 5. 금지 — `docs/15` §5.1 과 같은 강도로

- `REGIME_TILT` 의 세 값을 결과를 보고 옮기지 않는다.
- `cycle_class` 를 8종에서 늘리거나 쪼개지 않는다.
- 레짐이 J·C·구획을 건드리게 하지 않는다.
- 거시 변수 목록을 코드에 고정하지 않는다 — 분석가가 증거와 함께 가져오고, **어떤 변수를
  봤는지는 산출물에 남는다.** 코드가 변수를 고르면 그것이 L2 의 자유도 폭발이다.
- 레짐이 없으면 **계수 1.0** 이다. 없는 것을 역풍으로 읽지 않는다.

## 6. 결과별 조치 — 미리 고정한다

| 관측 | 조치 |
|---|---|
| 레짐 판정이 매주 뒤집힌다 | **그 사실을 리포트에 싣는다.** 계수를 줄이지 않는다 — 판정이 불안정하다는 것 자체가 사람이 알아야 할 정보다 |
| 8칸 중 대부분이 `neutral` 로 몰린다 | 기록만 한다. "분석가가 겁이 많다" 는 해석과 "실제로 중립이다" 를 구분할 방법이 없다 |
| 사용자가 레짐 판정에 반복적으로 반대한다 | **사람 판정으로 덮어쓰는 경로**를 연다 (`--human-regime`). 계수는 안 건드린다 |
| 크레딧이 부담된다 | 주간을 격주로 늦춘다. 계수는 안 건드린다 |
