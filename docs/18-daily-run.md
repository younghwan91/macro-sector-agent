# 18. 실전 운영 — 무엇을 언제 돌리고, 나온 것을 어떻게 읽는가

작성 2026-08-25. 대상 독자는 **이 시스템을 돌려서 돈을 벌 사람**이다. 설계 근거는 각
문서(`02` 스캔 · `04` 가치함정 · `05` 에이전트 · `06` 종목 · `07` 포트)에 있고, 여기에는
**순서와 판단**만 적는다.

---

## 0. 이 시스템이 하는 일과 하지 않는 일

**한다:** 미국 상장 19,717 종목을 134개 산업 테마로 묶고, ① 오래 잊혀진 테마를 찾아
② 그것이 *바닥*인지 *죽어가는 중*인지 판별하고 ③ 그 테마 안에서 재무가 버티는 종목의
**명단**을 낸다.

**하지 않는다:** 종목을 추천하지 않는다. 진입 시점을 정하지 않는다. 주문을 내지 않는다
(`CLAUDE.md` §8). 명단을 받은 뒤 **무엇을 언제 살지는 사람이 차트를 보고 정한다.**

역할 분담은 이것이 전부다:

| | 누가 | 무엇을 |
|---|---|---|
| 테마 선택 | **시스템** | 이게 시스템의 최우선 임무다 |
| 함정 판별 | **시스템** | 명단에 올릴 자격이 있는지 |
| 종목 명단 | **시스템** | 결정론적 계층이 고른다 (`CLAUDE.md` §4) |
| **종목·시점·비중** | **사람** | 차트·손익비를 보고 |

## 1. 세 개의 명령

```bash
cd ~/Documents/git/macro-sector-agent

uv run msa scan --top 20                                    # ① 오늘의 테마 순위   (~2분)
uv run msa research <theme> --record state/fixtures         # ② 함정 판별          (5~10분)
uv run msa picks <theme>                                    # ③ 종목 명단          (~10초)
```

순서는 고정이다. **②를 건너뛰고 ①에서 ③으로 가면 안 된다** — 그것이 가치 함정을 사는
경로다. 2026-08-24 스코어보드 1위였던 `media_streaming` 은 ②에서 편입 불가로 걸렸다.

### ① `msa scan` — 무엇을 계산하나

6개 블록을 테마마다 계산한다. **A·B 는 자격 조건이고, C·E·F 가 순위다** (S2 집계, `docs/12` §4.3):

| 블록 | 묻는 것 | 쓰임 |
|---|---|---|
| **A** 망각 | 얼마나 오래 소외됐나 (유동성 고갈·고점 후 경과) | `mean(A,B) ≥ 0.5` **자격** |
| **B** 거래 고갈 | 팔 사람이 다 팔았나 | 〃 |
| **C** 전환 | 지금 돌기 시작했나 | 순위 |
| **E** 재무 | 재무가 버티나 | 순위 |
| **F** 밸류 | 싼가 | 순위 |
| **D** | (참고 열) | |

**순위가 높다 = "주가가 오래 죽어 있다"** 일 뿐이다. 망한 회사도 주가는 오래 죽어 있다.
그래서 ②가 있다.

산출물: `state/scans/<date>/` (`scoreboard.csv` · `indicators.csv` · `coverage.csv` · `meta.json`)

### ② `msa research` — 판별기

에이전트 4명이 각자 웹 검색을 하고, **확신도와 게이트는 파이썬이 계산한다.**
에이전트는 근거만 낸다 (`CLAUDE.md` §3).

| 역할 | 하는 일 | 비고 |
|---|---|---|
| `supply_analyst` | 공급이 줄었나 (설비투자·폐업·감산) | |
| `catalyst_analyst` | 지금 돌 이유가 있나 | |
| `bear` | **이거 그냥 망한 것 아닌가** | **스코어보드를 안 준다** — 순위에 휘둘리지 않게 (`BearInputs`) |
| `referee` | 셋을 놓고 판정 | |

판별의 중심 질문은 하나다:

> **주가는 죽었는데, 실제로 그 물건을 쓰는 양도 줄었나?**
>
> - 쓰는 양 그대로 · 주가만 죽음 → **잊혀진 것** → 후보
> - 쓰는 양 자체가 영구히 줄어듦 → **죽어가는 것** → 탈락

산출물: `state/theses/<date>/<theme>.thesis.yaml` · `.report.md` ·
`rejections-pending.yaml` · `contested.json`

### ③ `msa picks` — 명단

하드 제외(E1~E6)를 통과한 **적격 종목 전부**를 테마 내 동일가중으로 낸다.
S·T·M 3축과 순위는 함께 나오지만 **선정에 쓰이지 않는다 — 관찰 지표다** (`docs/15` 검정 결과).

> **명단에 올랐다 = "함정이 아니라고 판정됨" 이 아니라 "판정 절차를 거치지 않음" 이다.**
> 종목 단위 가치함정 판별은 없다. 판별은 테마 단위(②)에서만 한다.

## 2. 나온 것을 어떻게 읽나

### ② 의 결론은 두 줄이다

```
cycle_confidence : 0.45
편입 가능        : False
```

- `cycle_confidence` 는 **파이썬이 재계산한다.** 저장 직전 파일 자신의 축 판정으로 다시
  도출해 대조하고, 다르면 **저장을 거부한다** (`schema.py` `R_CONFIDENCE_RECOMPUTE`).
  사람이나 에이전트가 손으로 적을 수 없다.
- `편입 가능: False` → **그 테마는 버린다.** 순위가 1위여도 버린다.
- 산식: `0.5(기본) ± 축별 항`. 0.5 미만이면 편입 불가 (`docs/07` C6).

### 종료 코드

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 저장됨 | 판정 두 줄을 읽는다 |
| **2** | **스키마 미달 — 저장하지 않음** | **실패가 아니다.** 검증기가 부실한 논지를 거부한 것이다. 오류 목록이 무엇을 거부했는지 말해준다 |
| 3 | 제공자 오류 | 모델 호출 실패 — 다시 돌린다 |

**`--decision-date`.** 판정일은 기본이 오늘이고, 증거가 미래인지는 그 날짜로 잰다.
스캔 날짜(`--asof`)는 가격·재무가 끊긴 날이라 며칠 뒤처져 있는 것이 정상이다 — 그 둘을
같은 것으로 취급하면 실재하는 최신 문서가 전부 "미래" 로 거부된다(2026-08-25, 6/6 발생).
과거 시점을 되돌려 재현할 때만 `--decision-date` 를 명시한다.

종료 코드 2 에서 자주 나오는 것: 무효화 조건이 관측 불가능(`"재평가"` 같은 것),
`action` 이 허용값(`exit|halve|freeze_ladder`) 밖, **증거 날짜가 기준일 이후**
(`R_EVIDENCE_FUTURE`). 마지막 것은 2026-08-25 에 실제로 4건 잡혔다 — 에이전트가 문서
발행일 대신 **검색한 날짜**를 적고 있었다. **날짜는 절대 그럴듯하게 고쳐 적지 않는다. 그건 위조다.**

## 3. 돈 — 어느 경로가 무엇을 쓰나

| provider | 인증 | 비용 | 모델 |
|---|---|---|---|
| **`claude_code`** (기본) | 구독 로그인 | **API 크레딧 0** | 전부 **sonnet** (깊이는 `bear`·`referee` 만 high) |
| `fixture` | 없음 | **0 · 오프라인** | 없음 (녹화 재생) |
| `mock` | 없음 | 0 | 없음 (합성) |
| `anthropic` | `ANTHROPIC_API_KEY` | **크레딧 차감** | **haiku 만** (2026-08-25 지시) |

**"무료" 의 정확한 뜻:** 새로 나가는 돈이 없다는 뜻이지 공짜가 아니다. 구독 사용량은
소모되고, 많이 돌리면 한도에 걸릴 수 있다. 그때는 돈이 아니라 시간을 기다린다.

**반드시 알아야 하는 함정:** `ANTHROPIC_API_KEY` 가 환경에 있으면 `claude` CLI 는
그것을 **구독 로그인보다 우선**한다 — 그러면 크레딧으로 청구된다. Claude Code 는 매 호출에
시스템 프롬프트 ~35k 토큰을 붙이므로 사소한 호출 하나가 $0.09 였다(2026-08-25 실측).
`ClaudeCodeProvider._child_env()` 가 하위 프로세스 환경에서 그 키를 **지운다**.
회귀하면 조용히 돈이 나가므로 `test_l3_claude_code.py` 가 검사한다. 자세한 것은 `docs/05` §7.0·§7.1.

### 한 번 돌린 판정을 공짜로 다시 보기

```bash
uv run msa research <theme> --provider fixture --fixtures state/fixtures
```

`--record state/fixtures` 로 돌렸다면 역할 산출이 저장돼 있다. 재생은 **즉시·오프라인·$0** 이고,
**게이트나 스키마를 고쳤을 때 에이전트를 다시 부르지 않고 판정만 다시 계산**할 수 있다.
이것이 판별기를 고치는 정상 경로다.

## 4. 여러 테마를 동시에

테마별로 프로세스를 따로 띄우면 병렬이 된다. 한 개 돌리는 시간이면 여러 개가 끝난다.

```bash
for t in retail_department health_it home_improvement; do
  uv run msa research $t --record state/fixtures > /tmp/msa_$t.log 2>&1 &
done
wait
grep -H "편입 가능\|cycle_confidence" /tmp/msa_*.log
```

**라운드 파일 잠금이 필요한 이유(2026-08-25 수정).** `rejections-pending.yaml` 은
읽고→고쳐→쓰기다. 잠금이 없으면 늦게 끝난 테마가 먼저 끝난 테마의 기각 행을 **오류 없이**
지운다. `io.dir_lock()`(`fcntl.flock`)이 라운드 디렉터리를 잠근다.
`contested.json` 은 라운드 집계라 마지막에 쓴 프로세스의 관점이 남는다 — 찢어지지는 않지만
최신이 아닐 수 있다.

**처음에는 2~3개로 시작한다.** 구독 한도에 걸리면 그 테마만 실패하고 나머지는 산다.

**병렬로 돌려도 줄지 않는 시간이 있다.** 한 테마 안에서 `supply`·`catalyst`·`bear` 는 동시에
돌지만 `referee` 는 셋이 끝나야 시작한다. 2026-08-25 실측(6테마 동시, opus 배치):
촉매·공급 2~3분 → **베어 9분** → 심판. 베어가 라운드 전체의 병목이었고, 그래서 구독 경로의
기본 모델을 sonnet 으로 내렸다 (`docs/05` §7.1).

## 5. 지금 이 시스템의 한계 (숨기지 않는다)

1. **축 1(실물 수요) 은 45/134 테마만 선언돼 있다.** 그중 데이터가 있는 것이 27개,
   실제로 판정을 내는 것이 **23개**다(cycle 12 · warning 11). 나머지 111개는 판별 시
   `not_applicable` 이 되고, 축1·축3 이 모두 `not_applicable` 이면 게이트는 통과시키되
   **편입 불가**로 닫는다 (`gates.py`). 선언조차 안 된 89개는 실물 지표가 공개 통계로
   존재하지 않거나(`media_streaming` 시청시간, `health_it` 의료IT 지출) `source: manual` 이라
   사람이 넣어야 하는 것들이다(18개).
2. **참조 시계열은 발표 시차만큼 묵어 있다.** 실측 중앙값 1개월, 최대 4개월. 3개월까지만
   앞으로 끌어오고 그 이상은 채우지 않는다 (`PHYSICAL_STALE_TOL_MONTHS`). 몇 개월 묵은
   값으로 판정했는지는 `indicators.csv` 의 `unit_ref_lag_m` 열에 남는다.
3. **M3.5 관문은 FAIL 이다** (`docs/backtest-l1.md`) — 복합 점수의 rank-IC ≈ 0, C 블록만
   유효했다. 스코어보드는 "후보를 좁히는 장치"이지 검증된 알파가 아니다.
   성과 수치를 광고하지 않는다 (`CLAUDE.md` §7).
4. **`daily_bars` 는 배당 조정이 되어 있지 않다**(분할은 조정됨). 절대수익 백테스트에 주의.
5. **텔레그램 미설정** — `MSA_TELEGRAM_TOKEN`·`MSA_TELEGRAM_CHAT_ID`. 리포트는 파일로 남는다.
6. **`vcp_base` 의 남은 한계 둘**: 수축의 최신성을 요구하지 않고, dry-up 이 임계 없는
   순부등호다. 폭락 오탐은 2026-08-25 에 고쳤다 (`docs/06` §4). M 축은 관찰 지표라
   선정에 쓰이지 않는다.
7. **L5 가 못 재는 것**: 종목 고유 변동성이 L4 특성표에 없어 같은 테마 종목을 **상관 1**
   로 본다. 케이스 스터디가 비어 L_i(시나리오 손실) 경로가 형성되지 않아 C1 은 변동성
   기반만 구속한다. 바벨 라벨이 없어 앵커 비중은 **정한 것이 아니라 재지 못한 것**이다.
   전부 계획서 경고란에 매번 적힌다.

## 6. 데이터를 어떻게 최신으로 유지하나

**이 저장소는 데이터를 적재하지 않는다.** `Store` 는 `duckdb.connect(read_only=True)` 로 연다.
적재는 밖에서 일어나고, 여기는 읽기만 한다. 그래서 "스캔이 안 맞는다" 의 원인은 대개
**스토어가 뒤처진 것**이지 이 저장소의 버그가 아니다.

데이터는 네 갈래로 들어온다.

| | 무엇 | 어떻게 | 주기 | 없으면 |
|---|---|---|---|---|
| **①** | 주가·재무·상장정보 → `~/data/us_micro.duckdb` | `opt-factor ingest` (**`opt_portfolio` 저장소**) | **매일** | 스캔이 묵은 가격으로 순위를 낸다 |
| **②** | ETF 가격 (`funds.csv.zip`) | Airflow DAG 가 **매일** 받는다 (287MB) | 자동 | ETF 프록시 검증만 흐려진다 |
| **③** | 실물 수요 지표 · CPI | `msa data fred-fetch` | **월 1회** | 축 1 이 `data_missing` |
| **④** | 에이전트 근거 | 판별 시 자동 (웹 검색) | 매번 | — |

### ① Sharadar 일간 증분 — 매일

```bash
cd ~/Documents/git/opt_portfolio
uv run opt-factor ingest --store ~/data/us_micro.duckdb \
    --provider sharadar --tables sf1,sep,sfp,daily \
    --since $(date -d '-3 day' +%F)
uv run opt-factor status --store ~/data/us_micro.duckdb
```

3일치를 겹쳐 받는 것은 벤더의 사후 수정분을 잡기 위해서다. `SHARADAR_API_KEY` 가 필요하다.

> **`prices` 에 ETF 가 없어도 이제 스캔은 돈다 (2026-08-25 수정).**
> Sharadar 는 주식(`SEP`)과 펀드(`SFP`)를 다른 파일로 준다. 스토어를 어떤 경로로 빌드하느냐에
> 따라 `prices` 에 ETF 가 들어가기도 하고 안 들어가기도 한다 — 실제로 2026-08-25 재빌드가
> 돌자 **SPY 가 0행**이 되어 스캔이 통째로 멈췄다.
>
> SPY 는 RS·상대거래대금의 기준이라 없으면 C 블록이 무의미하다. 나머지 ETF 는 이미 벌크
> `funds.csv.zip` 에서 읽고 있었으므로 **SPY 만 스토어에 의존할 이유가 없었다.**
> `l1/panel._spy_series()` 가 스토어에 없으면 벌크로 넘어간다. 양쪽 다 없으면 예외다 —
> 조용히 비우지 않는다.
>
> **그래서 이 저장소 쪽에서 할 일은 없다.** 스토어에 ETF 를 넣고 싶다면 그것은 적재 쪽
> 결정이다 (이 저장소는 적재하지 않는다).
>
> **2026-08-27 — 적재 쪽 결정이 났다: `prices` 에 ETF 를 넣지 않는다.** 벌크 폴백이
> 임시방편이 아니라 **정식 경로**다. 근거는 ETF 행이 `prices` 에 들어가면 그 테이블을 읽는
> **모든** 소비자의 유니버스가 바뀌기 때문이고, 한 소비자 편의로 감수할 변경이 아니다.
> `funds.csv.zip` 은 DAG 가 매일 받으므로 폴백이 낡을 일도 없다.
>
> 그래서 `Store.close_series` 의 벌크 폴백 로그는 WARNING 이 아니라 **INFO** 다 — 이상이
> 아니라 설계다. 폴백이 **실패하면** 그때는 경고가 난다.
>
> 나중에 `prices` 에서 ETF 가 정말 필요해지면 방향은 **별도 테이블**(`etf_prices` 같은)로
> 합의됐다 — 기존 소비자를 건드리지 않으면서 정식 경로가 생긴다. 지금 할 일은 아니다.
>
> 위 `opt-factor` 명령은 `opt_portfolio/docs/factor-system/04-data-contract.md` §5 에서 옮겨
> 적은 것이고 이 저장소에서 검증하지 않았다. 실제로 이 기계의 스토어는 그 경로가 아니라
> Airflow DAG(`quant-airflow/dags/daily_sharadar.py`)의 **벌크 재빌드**로 만들어지고,
> 파일 소유자가 달라 사용자 계정으로는 쓸 수 없다. 적재 경로를 바꾸려면 그 저장소를 봐라.

**스토어가 뒤처지면 어떻게 되나.** 스캔은 스냅샷 시점 가격으로 순위를 내고, 판별은 **오늘 날짜
웹**을 본다. 그 간극 자체는 오류가 아니다 — 오늘 결정을 내리는 데 어제 가격을 쓰는 것뿐이다.
다만 간극이 보이지 않으면 나중에 원인을 못 찾으므로, thesis 에 `data_lag_days` 가 남고
7일(`DATA_LAG_WARN_DAYS`)을 넘으면 리서치 경고가 뜬다.

**적재 뒤에는 반드시 `msa data status` 를 본다** — 최신도와 행수가 함께 나온다.
`prices` 의 종목 수가 **줄었으면** 적재가 무언가를 지운 것이다. 최신도만 보고 넘어가지 마라.

**현재 상태 확인**은 `msa data status` — `prices`·`fundamentals` 의 `end` 가 스토어의 마지막 날이다.

### ② Sharadar 벌크 CSV — 손으로, 분기 1회

## 7.4 증거 실사 — 매일 자동으로 돈다

`msa run daily` 가 **편입 가능 테마의 근거만** 골라 원문을 받아 대조한다
(`msa ops audit-evidence <theme>` 로 따로도 돌린다). 편입 불가 테마는 건너뛴다 — 사지 않을
테마의 URL 수십 개를 매일 받을 이유가 없다.

무엇을 보는가: `claim` 에 적힌 숫자가 **그 문서에 실제로 있는지**. 스키마는 형식만 보므로
URL 이 실재하고 날짜가 미래가 아니면 통과하는데, 그러면서 원문에 없는 수치를 적을 수 있다.

| 상태 | 뜻 |
|---|---|
| `verified` | claim 의 숫자를 **전부** 찾았다 |
| `partial` | 하나 이상 못 찾았다 — 목록이 나온다. **먼저 열어라** |
| `unreachable` | 403·페이월·타임아웃. **맞다는 뜻도 틀리다는 뜻도 아니다** |
| `unsupported` | PDF 등 본문을 안 읽는 형식 |

**비율 임계를 두지 않는다** — 전부 찾아야 `verified` 다. "70% 이상" 같은 값은 근거 없이
고른 임계이고(`CLAUDE.md` §1), 무엇보다 **틀린 숫자 하나가 판정을 만든다.**

**단위 변환은 처리한다** (2026-08-26). 오탐의 가장 큰 원인이 이것이었다 — 한국어 "순손실
2,220만 달러" 가 영문 원문엔 `$22.2 million` 으로 있다. 이제 `만`·`억`·`조` 가 붙은 숫자는
원 단위와 천·백만·십억 표기를 함께 찾는다. 실측:

꼬리 0 도 맞춘다 — claim 의 `6.0%` 가 원문엔 `6 percent` 로 있다.

| | 이전 | 이후 |
|---|---|---|
| `partial` | 23 | **9** |
| `verified` | 13 | **27** |

*(`shipping_container` + `managed_care`, 판정을 만든 증거 46건)*

**넓히는 것은 찾는 쪽뿐이다.** 자리수를 바꾼 후보는 **숫자 경계까지** 본다 — `400만` 의
후보 `4` 가 `1,400`·`4.7` 안에서 걸리면, 넓히려다 검사를 꺼 버리는 것이다. 실제로 경계를
넣자 잘못 통과하던 2건(`[8]`·`[22]`)이 다시 잡혔다.

**남은 9건은 표기 문제가 아니다.** 반올림(`3,500만 명` ↔ `35.4 million`)이거나, 문서에
없는 수치다 — `[17]` 은 provider tax 설명 문서에 없는 `$340B`·`120만 명` 을 그 문서에
달았고, `[1]` 은 *2026년* 등록 현황 페이지에 2016~2021년 시계열을 달았다. 이런 것이
이 검사가 잡으라고 만든 것이다.

**이 검사가 못 하는 것: 문맥.** 숫자가 문서에 있어도 claim 이 말하는 뜻과 다를 수 있다.
실사(2026-08-25)에서 실제로 그런 사례가 있었다 — 원문의 "109 fewer counties" 를 "225개
철수" 로 적었다. 결국 판정을 만든 축의 근거는 사람이 원문을 읽어야 한다. 이 표는
**어느 것을 먼저 열지** 정해 줄 뿐이다.

## 7.5 편입 가능이 뜻하는 것과 뜻하지 않는 것

**`portfolio_eligible: True` 는 "가치 함정이 아니다" 이지 "지금 사도 된다" 가 아니다.**

5축은 전부 산업의 **사망 여부**를 묻는다. "자본이 지금 들어오는 중인가"(= 사이클의 어느
국면인가)를 묻는 항은 `docs/04` §4 에 **없다.** 2026-08-25 에 `shipping_container` 가 그 틈을
통과했다 — 논지 본문이 "사이클 진입 조건은 성립하지 않는다" 고 적었는데 편입 가능 0.75 가
났다. 설계 질문으로 등록했다 (`docs/19`), 그때까지 현행은 **표시뿐**이다.

**그래서 편입 가능 테마를 받으면 반드시 논지 본문(`claim`·`mechanism`)을 읽어라.**
게이트 숫자만 보고 사면 "들어가지 말라" 는 논지를 매수 신호로 읽게 된다.

## 7.6 증거를 믿기 전에 (2026-08-25 실사)

74건 표본에서 **약 20% 가 결함**이었다. 원문에 없는 수치, 잘못된 문서를 가리키는 URL,
2년 전 기사를 최근 것으로 이름만 바꾼 항목이 있었다. 판정 산식은 정확했지만 **그 산식에
들어간 근거가 부실했다.**

검증기가 이제 잡는 것: 자리표시자 날짜(`YYYY-MM-01`, 실측 309건 중 70건 = 23%) ·
자기 입력을 출처로 적는 것(`internal://`) · 미래 날짜 · 12개월 초과.

**원문에 없는 수치는 `msa ops audit-evidence` 가 잡는다** (§7.4, 2026-08-26 추가) — 매일
자동으로 돈다. 다만 **문맥은 여전히 못 본다.** 돈을 걸기 전에 `partial` 로 표시된 근거는
직접 열어 대조하라.

## 8. 절대 하지 말 것

- **스캔 순위만 보고 사지 않는다.** ②를 거치지 않은 테마는 후보가 아니다.
- **명단을 추천으로 읽지 않는다.** 명단은 "하드 제외를 통과했다" 이지 "좋다" 가 아니다.
- **증거 날짜를 고쳐 적지 않는다.** 검증기가 미래 날짜를 막지만, 막힌다고 날짜를 바꾸는 것은
  위조다. 증거를 바꿔야 한다.
- **편입 가능을 매수 신호로 읽지 않는다** (§7.5).
- **증거를 확인 없이 믿지 않는다** (§7.6) — 판정을 만든 근거만이라도 원문을 열어라.
- **탐색해서 가중치를 정하지 않는다** (`CLAUDE.md` §1). 구조를 바꾸려면 먼저 사전 등록
  문서를 쓴다 (`docs/12` · `14` · `15` · `17` 이 그 예다).
