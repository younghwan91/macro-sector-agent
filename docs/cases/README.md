# 케이스 스터디 라이브러리 — 가치함정 판별기 6건

`04-value-trap.md` §5 의 우선 6건(사이클 3 · 사망 3). 각 문서는 **판정 시점**의 5축 값을 사후 기입하고,
`04` §3 하드 게이트와 §4 확신도 규칙을 **기계적으로** 적용한 뒤, 역사적 결과와 일치했는지를 적는다.
기계 판독본은 `state/cases/cases.yaml` — M6 로더(`src/msa/l5/inputs.py`) 계약(`id·name_ko·type·theme_ids·clusters·drawdown_peak_to_trough·peak_date·trough_date·verified·sources[{url,title,date}]·notes`)의 상위집합이며, 주장 단위 인용은 `evidence[{claim,source_url,date,reliability}]` 에 따로 둔다.

> **이 파일들은 임계값 조정의 근거가 아니다.** 판정이 어긋나면 어긋났다고 적고 임계값은 그대로 둔다
> (`04` §5 · `10-validation.md` §7 · `CLAUDE.md` §1). 사망 사례의 낙폭만 `07-portfolio.md` §2.4 C1-(ii) 의
> `L_i` 입력으로 쓰인다 — 그것은 임계값이 아니라 손실 크기의 추정이다.

## 읽을 때의 주의

1. **사후 기입이다.** 출처의 발행일이 판정 시점 이후인 항목이 있다(예: 2013 연간 석탄 소비는 2015-04 발표). 각 문서의
   evidence 표에 날짜를 적었으니 PIT 여부는 거기서 읽는다. 판정에 쓴 수치는 가능한 한 판정 시점에 존재했던 값(STEO 의
   이듬해 1월 추정치 등)을 골랐다.
2. **시계열 가용성이 판정을 가른다.** 오프쇼어(리그 vs 생산), 몰 REIT(physical_ref 없음)에서 축 1 의 입력이 무엇이냐에
   따라 사망/경고/n/a 가 바뀐다. 이것은 임계값 문제가 아니라 **입력 정의** 문제이며, `themes.yaml` 의 `physical_ref` 결정으로
   돌아간다.
3. **규칙이 늦게 잡은 기록.** 석탄 2013 은 축 1 이 경고(10y −1.6%)였고 축 3 이 막았다. 2015 에야 축 1 도 사망이 된다.
   `04` §5 표의 "석탄 −4%/y" 는 5년 CAGR 이다.
4. **포화.** 탱커 2021 은 가점만 붙어 1.00 이 됐다. 계수는 선언이라 바꾸지 않으며, 캘리브레이션 대상으로 남긴다.
5. **버킷 이질성.** `reit_retail` 은 몰·스트립·NNN 혼합이라 버킷 낙폭(−64%)과 몰 REIT 낙폭(−77~−100%)이 다르다.
   `offshore_drilling` 은 육상 시추를 포함한다. `L_i` 에 어느 숫자를 넣는지 `07` 리포트가 명시해야 한다.
6. **성과 광고 아님.** 전방 수익률은 "규칙이 막았는가/통과시켰는가" 의 사후 대조용이지 전략 수익률이 아니다 (`CLAUDE.md` §7).

## 미검증 목록 (yaml `verified: false` 사유)

- silver-miners-2015: 은 산업용 수요 2005 값(10y CAGR) 1차 출처 없음 — 4y CAGR(+4.9%)·총수요 사상 최고는 확정.
- offshore-drilling-2016: 오프쇼어 리그 카운트 10y 연평균 시계열 없음 — IEA 생산 정체·IHS 1y 급감은 확정.
- tankers-2021: 발주잔량/선대 7.3%(1996 이후 최저)의 1차 출처 본문 미확인 — 해체 급증·TCE 음수는 확정.
- mall-reit-2018: 축 1 이 저장소 설정상 n/a; 그림자 시계열은 백화점 매출 프록시.

## 이 라이브러리가 하지 않는 것

- 임계값(−2%, 10%/35%, 0.5 등)과 §4 계수를 바꾸지 않는다.
- 11건 중 나머지 5건(우라늄·희토류·유선통신·육상 시추·중국 사교육)은 작성하지 않았다 — `04` §5 의 우선 6건만.
- M7 의 few-shot 투입은 별도 작업이다 (`11-roadmap.md`).
