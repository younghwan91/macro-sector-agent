# L1 백테스트 판정 — 관문 0 (M3.5 · 2026-08-23)

`docs/10-validation.md` §2 의 관문을 L1 스코어보드에 실제로 돌린 결과다. 답하는 질문은 하나 —
**"스코어보드를 순위 산출에 쓸 것인가"** (`docs/11-roadmap.md` M3.5). 가중치를 어떻게 고칠까가
아니다. 여기 적힌 어떤 수치로도 가중치·방향·임계를 옮기지 않았고 옮기지 않는다 (`CLAUDE.md` §1,
`docs/10` §2.4·§8). **선언과 어긋난 것도 그대로 적었다.**

재현: `uv run msa backtest l1` → `state/backtests/l1/2026-08-14/` (report.txt · ic_summary.csv ·
spread_summary.csv · breadth_lead_summary.csv · ic_indicator.csv · overfitting.json · exclusions.json).
코드: `src/msa/l1/backtest.py` (설계 상수와 근거는 모듈 머리말), DSR·PBO 는 `src/msa/vendor/overfitting.py`
(`portfolio-research` 벤더링, 커밋 b0e06e1f).

여기 적는 수치는 **스코어의 예측력**(rank-IC · 분위 스프레드 · 신뢰구간 · 시도 수를 명시한 DSR·PBO)이지
전략의 수익률이 아니다. CAGR·Sharpe·승률은 만들어지지 않는다 (`CLAUDE.md` §7).

## 5. `breadth_lead` 실측 — "브레드스가 지수보다 먼저 돈다" 에 숫자를 붙였다

정의 (`backtest.breadth_lead_episodes`): 에피소드 = 테마 EW 지수의 `above_200` 이 0→1 로 바뀐 월말
(1998–2026, 134 테마, **3,329 건**). 그 시점에 `breadth_200 ≥ 0.5` 런이 활성이면 lead = 전환월 − 런 시작월
(상한 없음; 지표 `breadth_lead` 는 12 로 자른다), 아니면 이후 12 개월 안 첫 브레드스 전환까지를 음수(lag), 없으면 none.

| 결과 | 값 |
|---|---|
| 브레드스가 **먼저** 돈 에피소드 (lead > 0) | **14.8%** (493 건). lead 중앙값 **2 개월** [p25 1, p75 7], 12 개월 초과 14% |
| **같은 달** (lead = 0) | **45.9%** (1,528 건) |
| 브레드스가 **뒤에** 돈 에피소드 (lag, 12M 안) | **35.9%** (1,196 건) |
| 12M 안에 브레드스가 돌지 않음 | 3.4% (112 건) |
| 반대 방향 — 브레드스 상향 전환 3,679 건 중 | 지수가 **이미 위** 84.5% (3,107) · 아직 아래였다가 12M 안에 따라옴 13.9% (512, 아래였던 것 중 89.5%) · 둘 다 아님 1.6% |
| 클래스별 lead>0 비율 | `secular_growth` 20.2% · `commodity_supply` 17.7% · `policy_program` 17.7% · `credit_rate` 15.1% · `secular_risk` 13.9% · `inventory` 13.2% · `capex_program` 11.9% · `discretionary_demand` 9.1% |

**읽기.** 동일가중 지수와 그 구성원 과반의 SMA200 돌파는 구성상 거의 같은 사건이고, 실측도 그렇다 —
**절반은 같은 달, 1/3 은 브레드스가 오히려 늦다.** 브레드스가 먼저 도는 15% 의 경우 리드는 대개 1~3 개월이다.
"브레드스는 지수보다 먼저 돈다" 는 **이 정의로는 일반 명제가 아니다.** 다만 §2 의 지표별 IC 에서
`breadth_200`·`breadth_nhnl` 은 `above_200` 과 같은 크기(+0.10~+0.12)로 일했다 — 브레드스가 **예측력이
없다**는 뜻이 아니라, 지수 전환에 **선행**한다는 주장이 숫자로 뒷받침되지 않는다는 뜻이다. 지표 `breadth_lead`
자체의 단독 IC 는 +0.006~+0.011 로 0 이다.

## 7. 과최적화 정산 — 시도 수를 세어 적는다

**시도 수 규칙** (`backtest.count_trials`, `docs/10` §2.2): 선언된 복합 하나만 봤다면 1. 이 리포트는
블록 단독(+6)·호라이즌(×3)·클래스 파티션(+8)·두 창(×2)·지표 단독 IC(29 지표)·1M 월별 스프레드를
**전부 들여다봤다.** 들여다본 칸은 시도다.

```
608 = 창 2 × [ 변형 7 × 호라이즌 3 × (IC·스프레드 2 + 클래스 8) + 변형 7 × 1M + 지표 29 × 3 ]
```

| 대상 (주 창) | DSR N=1 (사전 선언) | DSR N=608 | 비고 |
|---|---|---|---|
| 복합 IC 12M, 비중첩 (n=15) | 0.868 | **0.020** | 둘 다 < 0.95 |
| 복합 IC 6M, 비중첩 (n=31) | 0.984 | 0.166 | |
| 복합 IC 3M, 비중첩 (n=62) | 0.927 | 0.042 | |
| 복합 1M 스프레드 (n=186, 중첩 없음) | 0.994 | 0.223 | |
| C 단독 IC 12M / 1M 스프레드 | — | 0.094 / 0.866 | C 조차 608 시도로 정산하면 0.95 미만 |
| 전 구간 복합 1M 스프레드 (n=342) | 1.000 | 0.595 | |

중첩 그대로의 DSR(낙관치)은 `overfitting.json` 에 있다 (복합 12M 주 창 N=1: 1.000 / N=608: 0.59).

**PBO** (CSCV S=16, 12,870 조합 전수, 전략 = 복합 + A~F 단독 7 개의 월별 스프레드): 주 창 1/3/6/12M =
0.006 / 0.008 / 0.003 / 0.033, 전 구간 0.000 / 0.003 / 0.004 / 0.098. **해석 주의** — PBO 는 "IS 최고
전략이 OOS 에서 중앙값 아래로 떨어지는 빈도" 다. 여기서 IS 최고는 거의 항상 C 단독이고 OOS 에서도 C 가 위다.
낮은 PBO 는 **변형 간 순위(C ≫ 복합 > B·E ≫ F > D > A)가 시간상 안정적**이라는 뜻이지 복합 스코어가 좋다는
뜻이 아니다. 7 개 변형 중 하나를 고르는 선택 절차가 과적합이 아니라는 말이고, 우리는 그 선택을 하지 않았다
(복합은 선언됐다).

## 9. 이것으로 무엇을 하는가 — 그리고 하지 않는가

**한다**
- 판정을 기록한다: **FAIL (주 창·12M)**. `docs/11-roadmap.md` M3.5 체크박스에 반영.
- `docs/10` §2.3 첫 행의 조치 — "L1 을 순위 산출에 쓰지 않는다. 관찰 지표로 강등하고 그 사실을 README 에
  적는다" — 는 **M5·M6 의 입력이 바뀐다는 뜻**이다 (`docs/11` "순서를 바꾸면 안 되는 네 곳" 4). 스코어보드는
  계속 산출되고 블록 프로필은 계속 읽히지만, **복합 `score` 의 순위를 상위 K 선정의 근거로 쓰는 것은 이 판정이
  서 있는 동안 정당화되지 않는다.** README 에 한 줄 적었다.
- 선언의 근거를 다시 읽는다 (§3): `commodity_supply` 의 E 0.30 · `capex_program` 의 F 0.35 · `credit_rate`
  `secular_growth` 의 D. 다시 읽는 것은 문서(`docs/02` §7 의 "가중치 근거")이고, 고치는 것이 있다면 **도메인
  근거와 함께 별도 커밋**이며 이 표의 숫자를 근거로 쓰지 않는다.
- A 와 D 가 **반대 부호**라는 사실은 가중치가 아니라 **설계**의 문제로 읽는다 — A 는 "어디를 볼지" 의 전제
  조건이지 "언제 살지" 의 신호가 아니라고 `docs/02` §8 이 이미 말한다. 그 전제 조건이 가중합에 **선형으로
  더해지는 것**이 맞는지는 설계 질문이다. 이 문서는 질문을 적어 두기만 한다.

**하지 않는다**
- 가중치·방향·임계·K 를 바꾸지 않는다. 이 문서의 어떤 표로도. (`CLAUDE.md` §1, `docs/10` §2.4·§8)
- "C 만 쓰면 된다" 고 결론 내리지 않는다 — 그것이 바로 608 시도 중 최선을 고르는 행위이고, C 의 DSR(N=608)
  은 0.09~0.87 이다.
- 전 구간이 통과했다는 이유로 주 창의 실패를 없던 일로 하지 않는다. 창은 결과를 보기 전에 정했다.
- 이 수치를 성과로 공표하지 않는다 (`CLAUDE.md` §7).

(iv) 저널 항목 — 을 하나의 별도 커밋으로. 이 절은 결과를 기록할 뿐 채택하지 않으며, 그 결정의 입력으로
위의 DSR·12M 스프레드·클래스별 한계를 함께 읽기를 요구한다. 둘 다 합격이 아니므로 "단순한 쪽 우선" 조항은
발동하지 않는다. **S3 는 만들지 않는다.**

## 13. 후속 (2026-08-23) — S2 채택 이후 이 문서를 읽는 법

S2 가 채택돼(`docs/12` §8) `scoreboard.py` 의 `score` 는 이제 §12 의 S2 이고, 구 복합은 `score_s0` 로 남는다.
따라서 **§0–§11 은 구 복합(S0)에 대한 기록**이며 그대로 둔다. 앞으로 `uv run msa backtest l1` 이 내는
`score` 변형은 S2 를 재고, `msa backtest l1-structures` 는 S0·S1·S2 를 나란히 잰다. 새 캐시로 다시 돌릴 때는
§10 대로 새 절을 덧붙인다.
